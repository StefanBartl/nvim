# lib.nvim — New Module Candidates

Generated by a parallel multi-agent scan of all personal plugins in `E:\repos` (2026-07-14).
Each entry names a proposed home inside `lib.nvim`, a short description, and every place in the
surveyed plugins that already implements the same (or near-same) thing — with absolute paths and
line numbers so the actual code can be pulled up directly. Entries flagged **"seen in N plugins"**
independently reimplement the same idea and are the strongest candidates — that's a real recurring
gap, not a one-off.

`filetreepicker.nvim` and `mygrep.nvim` were **not analyzed** — both are commented out in
`lua/plugins/personal/init.lua` and are not checked out under `E:\repos`.

---

## Debounce / throttle — strong, recurring (seen in 5 plugins)

No debounce/throttle primitive exists anywhere in `lib.nvim` today. The same
libuv-timer-cancel-and-restart pattern is hand-rolled independently at least five times:

- `E:\repos\pickers.nvim\lua\pickers\selected_index\debounce.lua:1-56` — `M.debounce`, libuv timer + `vim.defer_fn` fallback, proper cleanup handle.
- `E:\repos\reposcope.nvim\lua\reposcope\utils\protection.lua:22-42` — `M.debounce`, near-duplicate of the above.
- `E:\repos\color_my_ascii.nvim\lua\color_my_ascii\debounce_manager.lua:1-260` — adaptive per-buffer debounce (delay scales with buffer size), timer bookkeeping, auto-cleanup on `BufDelete`. Most feature-complete implementation seen — good reference for the real API shape.
- `E:\repos\filetree.nvim` — the same per-timer debounce pattern repeated near-identically across ~9 files, e.g. `lua\filetree\features\nav\cwd_sync\init.lua:190-201`, plus `auto_reveal`, `opened_sync`, `current_hl`, `search/filter`, `watcher_quarantine`, `git_status`.
- `E:\repos\markdown.nvim\lua\markdown_nvim\core\table_mode.lua:87-100` — inline `uv.new_timer()` debounce, re-entrancy-guarded start/stop/close.

**Proposal:** `lib.nvim.debounce(fn, ms)` (and maybe a buffer-scoped variant modeled on color_my_ascii's `debounce_manager.lua`).

## Async process spawn with captured stdout/stderr + timeout — recurring (seen in 3 plugins)

`lib.nvim.cross.run`/`run_argv` cover blocking calls and shell-string async; `cross.uv.spawn_command`/
`spawn_shell_command` cover fire-and-inherit-stdio. None of them cover "spawn argv, buffer
stdout/stderr, invoke callback(response, err), with an optional timeout" — reimplemented at least
9 times combined across two plugins:

- `E:\repos\pdfport.nvim\lua\pdfport_nvim\backends\pdftotext.lua:44-124` (same shape repeated in `backends\docling.lua`, `pdfplumber.lua`, `ollama.lua`, `claude.lua`, `marker.lua` — 6 copies total).
- `E:\repos\reposcope.nvim\lua\reposcope\network\request_tools\curl.lua`, `wget.lua`, `gh.lua` (~100-140 lines each, 3 near-identical copies).
- `E:\repos\language.nvim\lua\language\util\job\init.lua:1-145` — cancellable, timeout-bounded, argv-based (prefers `vim.system`, falls back to `jobstart`), including Windows `.cmd`/`.bat` shim resolution via `cmd.exe /c`. Most complete implementation — good reference.

**Proposal:** `lib.nvim.cross.uv.spawn_capture(argv, { timeout_ms, on_done })` (async, buffered output, optional cancel+timeout). Absorbs `language.nvim`'s job runner too if scope allows.
