# `nvim-containers`

Refactor nvim-containers adapters to return ok/err
In the nvim-containers repo (E:\repos\nvim-containers), the low-level adapter modules under lua/containers/adapters/{docker,podman,wsl}/ (e.g. list_containers.lua, get_logs.lua, kill_container.lua, prune_containers.lua, remove_container.lua, start_container.lua, stop_container.lua, list_images.lua, prune_images.lua, remove_image.lua, list_distros.lua, start_distro.lua, stop_distro.lua — roughly 20 files) are pure backend modules (they shell out to docker/podman/wsl CLIs and parse JSON) but currently call the notify wrapper directly (require("containers.notify")) to report errors/success, rather than returning ok/err and letting the calling command layer (lua/containers/bindings/usrcmds/*.lua) decide whether/how to notify. Per the project's UI-decoupling convention (see FINISH_ARCH.md in the main nvim config for the precedent), low-level modules should return ok, err (or a value + nil-on-failure plus a separate error string) instead of notifying directly.

Fixing this properly requires: (1) changing each adapter function's return signature to surface success/failure/error text instead of notifying inline, (2) threading that result through the corresponding lua/containers/core/usecases/**/*.lua passthrough layer, and (3) updating each call site in lua/containers/bindings/usrcmds/container_commands.lua, container_commands_buffer.lua, image_commands.lua, and wsl_commands.lua to check the result and notify appropriately (many already do partial pcall-based error handling around the usecase calls, so this needs careful review per call site to avoid double-notifying or losing error messages).

This is a genuine architecture violation (confirmed by reading list_containers.lua, kill_container.lua, get_logs.lua, and their usecase/binding call chains) but is a multi-layer, ~20+ file refactor that's too large and risky to do as a blind mechanical pass — it needs per-call-site review of how each command handler currently surfaces errors (some use pcall + vim.inspect on the error, some just check a boolean). Recommend doing this as its own dedicated, carefully-tested change, starting with one vertical slice (e.g. the container list/start/stop/kill/remove chain) as a template before repeating the pattern for images and wsl.
