# Misc — events, actions and features that are not keymaps, usercmds or autocmds

Everything a personal plugin exposes that does not fit the three BINDINGS
sheets: background surfaces, persisted state, servers, generated artifacts.

---

## documentation.nvim

Added 2026-07-28.

### Generated artifacts

Written into `opts.out_dir` (default `docs/map/`) by `:DocMap`:

| File | What |
| --- | --- |
| `index.html` | The interactive map: Tree, Hierarchy, Notes, Index, History, Analysis. Self-contained — no CDN, no build step. |
| `overview.md` | The same tree as Markdown, renders on GitHub. |
| `module_map.json` | The IR, **byte-deterministic**. What `--check` compares and what `:DocMap diff` reads out of old commits. |
| `coverage.svg` | Optional (`opts.badge`), hand-rolled, no network call. |

Plus, in that repo only, `docs/BINDINGS.md` — generated by
`documentation.bindings.docs` from the live `KEYS` table and the autocmd/usrcmd
manifests, written by `scripts/gen_map.lua` and skipped under `--check`.

### Persisted state

- **Saved trails** — `stdpath("state")`, keyed by repository root. Pins survive
  Neovim sessions. Deliberately *not* in the repository: a trail has no more
  claim on the project than a jumplist has.

### Local server

`:DocMap serve` starts an HTTP server. Security properties (documented in that
repo's `docs/SECURITY.md`, each with a spec):

- binds **`127.0.0.1` only**, never `0.0.0.0`;
- **port 0** — the OS assigns, so there is nothing predictable to find;
- dies with the editor via `VimLeavePre`;
- `safe_sha()` accepts `^%x%x%x%x%x%x%x+$` up to 40 chars and nothing else —
  even `HEAD` is refused, because a whitelist that makes exceptions stops being
  one;
- `safe_static_name()` accepts a bare filename inside `out_dir`; anything with a
  separator or a `..` segment is refused.

It exists only because a `file://` page cannot `fetch`, so the History tab needs
an origin.

### Subprocesses

`git` (diff/impact/churn/serve/history) and `lua-language-server` (only under
`:DocMap full`, with a timeout). **Every** call goes through `vim.system` with
an argv array — no `io.popen`, no `os.execute`, no shell anywhere in `lua/`.
That is what makes a user-typed `<ref>` safe.

### Drift checks

The half that is not a rendering. `:DocMap check` / `--check` produce
`Documentation.Finding[]`: missing or mismatched `@module`, require cycles,
undeclared requires, layer violations (`opts.layers`), documentation coverage,
dead code (`opts.dead_code`), duplicates. Errors fail CI and the pre-commit
hook.

### Embedding API — no commands attached

`require("documentation")` registers nothing. For another plugin:

- `generate(opts)` — one-shot scan/check/render;
- `install(opts)` → a live handle: an in-memory IR, optional rescan-on-save,
  `on_change` subscribers. What a consuming plugin should use instead of
  parsing `module_map.json` off disk;
- `uninstall(handle_or_root)` — idempotent.

### Which-key

Registers `:DocBrowse`'s buffer-local keys when which-key is installed
(`opts.which_key`, default true; v3 `wk.add` / v2 `wk.register`, guarded by
`pcall`). No-op without it.
