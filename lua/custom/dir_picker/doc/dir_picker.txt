1. INTRODUCTION                                    *dir_picker-introduction*

dir_picker opens a file picker (Telescope or fzf-lua) rooted at a directory
determined by a numeric depth above the current working directory, or by a
named alias such as `git`, `home`, or `root`.

All inner modules are lazy-loaded; the entry point adds zero milliseconds
to Neovim startup time.

==============================================================================
2. SETUP                                                  *dir_picker-setup*

Call `setup()` once from your plugin loader or init.lua: >

    require("custom.dir_picker").setup({
      default_engine  = "telescope",
      fallback_engine = "fzf",
    })

Passing no arguments uses the built-in defaults.

==============================================================================
3. CONFIGURATION                                         *dir_picker-config*

`setup()` accepts a |DirPickerConfig| table with the following fields:

    default_engine   string     "telescope" or "fzf". Used when no engine
                                argument is given. (Default: "telescope")

    fallback_engine  string     Engine to try if default is unavailable.
                                (Default: "fzf")

    depth_aliases    table      Map of alias name → function() → string.
                                Each function must return an absolute path.
                                Built-in aliases (cwd, home, root, git) can
                                be overridden here.

Example — add a custom alias: >

    require("custom.dir_picker").setup({
      depth_aliases = {
        work = function() return vim.fn.expand("~/work") end,
      },
    })

==============================================================================
4. USER COMMAND                                         *dir_picker-command*

                                                           *:DirPicker*
    :DirPicker [arg ...] [engine]

    Arguments may appear in any order. Three forms are accepted for the
    location argument:

    Numeric depth~
        An integer ≥ 0. 0 (the default) means the current working directory.
        Each increment ascends one directory level.

    Named alias~
        One of the built-in names (cwd, git, home, root) or any custom alias
        registered via |dir_picker-config|. See |dir_picker-aliases|.

    Explicit path~
        A token starting with `path=` followed immediately by the target
        directory. The value is expanded and normalized: ~ is replaced with
        the home directory, $VAR and %VAR% environment variables are resolved,
        and path separators are normalized for the current platform.

        path=/srv/www
        path=c:\tools
        path=~/projects
        path=%USERPROFILE%\dev
        path=$XDG_DATA_HOME

    Priority: if both a depth/alias and a path= token are present, path=
    takes precedence.

    [engine]   "telescope" or "fzf". Overrides the configured default for
               this single invocation.

    Tab-completion is available for all argument types.

Examples: >

    :DirPicker
    :DirPicker 2
    :DirPicker git
    :DirPicker home fzf
    :DirPicker path=/srv/www
    :DirPicker path=c:\tools
    :DirPicker path=~/projects telescope
    :DirPicker path=%USERPROFILE%\dev fzf
==============================================================================
5. KEYMAP                                                 *dir_picker-keymap*

    <leader>fd   (normal mode)

    Opens a two-step interactive prompt:

    Step 1: |vim.ui.input| — enter one of:
              • a depth integer (e.g. 2)
              • an alias name  (e.g. git)
              • a path= value  (e.g. path=c:\tools  or  path=~/work)
            Empty input → CWD.
            <Esc> → abort silently.

    Step 2: |vim.ui.select| (or lib.ui.hover_select when available) —
            choose the picker engine.

==============================================================================
6. PROGRAMMATIC API                                          *dir_picker-api*

    core.pick({depth_arg}, {engine_arg}, {raw_args})  *dir_picker.core.pick()*

    Parameters: ~
        {depth_arg}   integer|string|nil   Depth integer or alias name.
        {engine_arg}  string|nil           "telescope" or "fzf".
        {raw_args}    string[]|nil         Full token list; scanned for
                                           path= entries. Overrides depth_arg
                                           when a path= token is found.

    Examples: >

        local core = require("custom.dir_picker.core")

        core.pick()                                -- CWD, default engine
        core.pick("git")                           -- nearest Git root
        core.pick(2, "fzf")                        -- 2 levels up, fzf-lua
        core.pick(nil, nil,  { "path=/srv/www" })  -- explicit path
        core.pick(nil, "fzf", { "path=c:\\tools" })
==============================================================================
7. DEPTH ALIASES                                         *dir_picker-aliases*

Built-in aliases:

    cwd    Current working directory (vim.uv.cwd()).
    home   User home directory (vim.uv.os_homedir()).
    root   Filesystem root, reached by walking parent directories upward.
    git    Nearest ancestor directory that contains a `.git` entry.

Custom aliases are registered via the `depth_aliases` field in |dir_picker-config|.
Each value must be a zero-argument function returning an absolute path string.

==============================================================================
8. ARCHITECTURE NOTES                               *dir_picker-architecture*

- Zero global state: all state lives in module-local variables.
- pcall-guarded requires throughout; no silent failures.
- Engine availability is probed at call time, not at startup.
- Path resolution uses vim.fs.normalize and vim.uv — no shell spawning.
- lib.notify, lib.map, lib.usercmd, lib.ui.hover_select are used where
  available; each has a stdlib fallback.
