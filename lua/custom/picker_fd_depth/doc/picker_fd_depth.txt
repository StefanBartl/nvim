1. INTRODUCTION                                  *picker_fd_depth-introduction*

picker_fd_depth is a lightweight, ultra-performant Neovim module designed
to run path-agnostic file searches targeting specific parent directory depths
above the active current working directory (CWD).

It features pluggable engine routing natively compatible with both Telescope
and fzf-lua, wrapped inside robust user interactive interfaces.

==============================================================================
2. FEATURES                                            *picker_fd_depth-features*

  - Dynamic Traversal    Search files N levels above CWD instantly.
  - Multi-Engine         Seamlessly switch between Telescope and fzf-lua.
  - 100% Lazy-Loaded     Zero millisecond overhead added to Neovim startup.
  - Abort Protection     Interrupted UI entries cleanly terminate execution.
  - Cross-Platform       Optimized for Linux, macOS, Windows, and WSL.
  - Autocompletion       Smart command line argument completion for engines.

==============================================================================
3. SETUP                                                  *picker_fd_depth-setup*

Initialize the module via your config files using standard conventions:
>
    require("custom.picker_fd_depth").setup()
<
This will securely bind user commands via your framework's |lib.usercmd|
and setup keymaps via |lib.map|.

==============================================================================
4. USAGE                                                  *picker_fd_depth-usage*

4.1 USER COMMANDS                                *picker_fd_depth-commands*

The module exposes the following structured command interface:

    :FindFiles [depth] [engine]

Parameters:
    [depth]   Integer signifying folder layers to traverse up (Default: 0).
    [engine]  Search backend engine: "telescope" | "fzf" (Default: telescope).

Examples:
>
    :FindFiles        " Search current directory using Telescope
    :FindFiles 2      " Search 2 levels above CWD using Telescope
    :FindFiles 1 fzf  " Search 1 level above CWD using fzf-lua
<

4.2 KEYMAPS                                        *picker_fd_depth-keymaps*

Default keymap registration:

    <leader>fdd       Triggers the interactive sequential search prompt.

The mapping executes two safe sequential inputs:
  1. Requests target level upwards via |vim.ui.input|.
  2. Requests engine choice via project standard UI |lib.hover_select|.

Pressing <Esc> at any point aborts the process immediately with no side-effects.

==============================================================================
5. PROGRAMMATIC API                                         *picker_fd_depth-api*

Execute low-level functions within custom scripts or hooks:
>
    local core = require("custom.picker_fd_depth.core")

    -- Search 3 directory levels above using fzf-lua
    core.find_files(3, "fzf")
<

==============================================================================
6. PERFORMANCE & SAFETY DESIGN                     *picker_fd_depth-architecture*

Built defensively around high-grade enterprise software principles:

  - Lazy Load Boundary: Core search modules and dependency paths remain
    completely un-required until the user actively fires a search command.
  - Allocation Hardening: Avoids costly OS shell loops during path calculation
    by utilizing optimized string multiplication and native |vim.fs.normalize|.
  - Directory Guards: Validates path integrity using |vim.fn.isdirectory|
    prior to executing pickers to avoid freezing UI buffers on dangling paths.

==============================================================================
7. TROUBLESHOOTING                               *picker_fd_depth-troubleshooting*

7.1 PATH DOES NOT EXIST ERROR
If you receive a notification stating the resolved path does not exist, you
have requested a depth level that exceeds the root boundaries of your
operating system storage layer. Lower the depth argument integer.

7.2 INTERRUPTED ABORTS
If you accidentally hit <leader>fdd and wish to close the prompt, hit <Esc>
during the level input prompt. The script will close gracefully without
forcing a secondary menu selection.
