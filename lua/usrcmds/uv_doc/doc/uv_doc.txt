1. INTRODUCTION                                         *uv_doc-introduction*

UVDoc provides integrated libuv API documentation directly in Neovim by
fetching RST source files from the official libuv documentation site at
https://docs.libuv.org/en/v1.x/

Features:~
  • Exact and fuzzy symbol lookup
  • Interactive symbol picker with cursorline navigation
  • C signature extraction from RST sources
  • Command-line completion for all uv_* symbols
  • Aggregated genindex parsing (handles split pages automatically)
  • Session-based caching with explicit invalidation
  • Lazy-loading for minimal startup overhead

==============================================================================
2. REQUIREMENTS                                         *uv_doc-requirements*

  • Neovim ≥ 0.9 (requires |vim.system()| API)
  • curl in PATH (Linux/macOS)
  • Internet connection for documentation retrieval

==============================================================================
3. COMMANDS                                                 *uv_doc-commands*

                                                                     *:UVDoc*
:UVDoc [name]           Show documentation for a libuv symbol.

                        Behavior:
                        • Exact names (uv_timer_start) open directly
                        • Fuzzy queries (timer, fs_event) show picker
                        • No argument uses word under cursor

                        Examples:
>
                        :UVDoc uv_timer_start
                        :UVDoc timer
                        :UVDoc vim.uv.new_tcp
<

                                                                 *:UVDocList*
:UVDocList [query]      Open interactive symbol list with optional filter.

                        Examples:
>
                        :UVDocList          " All symbols
                        :UVDocList fs       " Filesystem functions only
                        :UVDocList tcp      " TCP functions only
<

                                                                 *:UVDocHere*
:UVDocHere [name]       Insert C signature at cursor position.

                        Behavior:
                        • Functions inserted as markdown code block
                        • Type definitions as comment line
                        • Fuzzy matching like :UVDoc

                        Examples:
>
                        :UVDocHere uv_fs_stat
                        :UVDocHere loop
<

                                                           *:UVDocCacheClear*
:UVDocCacheClear        Clear all session caches (genindex and symbol list).

4. CONFIGURATION                                       *uv_doc-configuration*

Default configuration can be customized via the config module:
>
    local uv_doc = require("usrcmds.uv_doc")
    local config = require("usrcmds.uv_doc.config")

    -- Customize configuration
    config.set({
      open = "float",         -- "float" or "split"
      max_bytes = 512 * 1024, -- Max HTTP response size
      timeout = 15000,        -- HTTP timeout (milliseconds)
      user_agent = "uvdoc.nvim/0.4",
    })

    -- Register user commands
    uv_doc.enable_usercmd()
<

Configuration Options:~

  open          (string)  Display mode: "float" or "split"
                          Default: "float"

  max_bytes     (integer) Maximum HTTP response size in bytes
                          Default: 524288 (512 KB)

  timeout       (integer) HTTP request timeout in milliseconds
                          Default: 15000

  user_agent    (string)  Optional curl User-Agent header
                          Default: "uvdoc.nvim/0.4 (+https://...)"

8. ARCHITECTURE                                         *uv_doc-architecture*

Module Structure:~
>
    usrcmds/uv_doc/
    ├── init.lua           # Main entry point with lazy-loading
    ├── @types.lua         # Type definitions
    ├── cache.lua          # Session caching
    ├── completion.lua     # Command-line completion
    ├── config.lua         # Configuration management
    ├── constants.lua      # URLs and constants
    ├── fetcher.lua        # Genindex aggregation
    ├── http.lua           # HTTP client
    ├── insert.lua         # Signature insertion
    ├── normalize.lua      # Symbol normalization
    ├── parser.lua         # HTML/RST parsing
    ├── search.lua         # Fuzzy search
    └── ui.lua             # UI rendering
<

Design Principles:~

  Single Responsibility   Each module has exactly one purpose
  Lazy-Loading            Submodules loaded only when needed
  Performance             Optimized for minimal startup overhead
  Error Handling          Type guards and pcall wrapping throughout

==============================================================================
9. PERFORMANCE                                           *uv_doc-performance*

First Request (Cold Cache):~
  Genindex aggregation:  ~500ms–2s
  Symbol extraction:     ~50–100ms

Subsequent Requests (Cache Hit):~
  Symbol lookup:         <10ms
  RST fetch:             200–500ms (not cached)

Optimizations:~
  • Genindex loaded only once per session
  • Symbol list kept in memory
  • Lazy-loading minimizes startup overhead
  • Array pre-allocation for known sizes
  • Local function references in hot paths

10. TROUBLESHOOTING                                 *uv_doc-troubleshooting*

"genindex unavailable"~

  Cause:    HTTP request failed or timeout
  Solution: • Check internet connection
            • Verify curl installation
            • Increase timeout: config.set({timeout = 30000})

"no uv_* anchors found"~

  Cause:    Genindex parsed but no symbols extracted
  Solution: • Clear cache: :UVDocCacheClear
            • Verify manually:
              https://docs.libuv.org/en/v1.x/genindex.html

"function signature not found"~

  Cause:    RST parsing could not extract signature
  Solution: • Automatic fallback to type extraction attempted
            • If persistent: report issue with symbol name
