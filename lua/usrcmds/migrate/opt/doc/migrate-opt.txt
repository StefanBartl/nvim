1. EINFÜHRUNG                                               *migrate-opt-intro*

Das migrate.opt Modul automatisiert die Migration von deprecated Neovim
Option API-Aufrufen zur aktuellen `nvim_get/set_option_value` API.

DEPRECATED APIS:
  • nvim_buf_get_option()
  • nvim_buf_set_option()
  • nvim_win_get_option()
  • nvim_win_set_option()

NEUE API:
  • nvim_get_option_value()
  • nvim_set_option_value()

Diese APIs wurden in Neovim 0.10+ als deprecated markiert und sollen
durch die neue, einheitliche Option-API ersetzt werden.

==============================================================================
2. INSTALLATION                                          *migrate-opt-install*

Füge in deiner Neovim-Konfiguration hinzu: >lua

    require("usrcmds.migrate.opt").enable()
<

Das registriert das `:MigrateOpt` Command.

ABHÄNGIGKEITEN:
  • telescope.nvim (für Picker-UI)
  • ripgrep (für CWD-Scan)

==============================================================================
3. VERWENDUNG                                              *migrate-opt-usage*

BASIC WORKFLOW:

1. Öffne File mit deprecated Option-API Aufrufen
2. Führe `:MigrateOpt %` aus
3. Wähle in Telescope die zu migrierenden Aufrufe
4. Drücke <CR> zum Anwenden

MODI:

Current Line Mode~
    Cursor auf Zeile → `:MigrateOpt`
    Wendet Migration sofort an (kein Picker)

Range Mode~
    Visual selection → `:MigrateOpt`
    Migriert alle Matches im Bereich

Buffer Mode~
    `:MigrateOpt %`
    Öffnet Picker mit allen Matches

CWD Mode~
    `:MigrateOpt cwd`
    Scannt rekursiv mit ripgrep

==============================================================================
4. KOMMANDOS                                            *migrate-opt-commands*

                                                                 *:MigrateOpt*
:MigrateOpt [args]
    Migriert deprecated Option API Aufrufe

    ARGUMENTE:

    Keine Argumente         Migriert aktuelle Zeile
    %                       Migriert ganzen Buffer (mit Picker)
    cwd                     Migriert alle Lua-Files in CWD (mit Picker)

    BEISPIELE: >vim
    :MigrateOpt                       " Aktuelle Zeile
    :MigrateOpt %                     " Buffer mit Picker
    :MigrateOpt cwd                   " CWD-Scan mit ripgrep
    :'<,'>MigrateOpt                 " Visual selection
<

PICKER KEYBINDINGS:

    <CR>        Wendet ausgewählte Migration an
    <Tab>       Multi-Select (nicht verfügbar - single_apply=true)
    <C-c>       Abbrechen

5. BEISPIELE                                            *migrate-opt-examples*

BUFFER OPTIONS~

Get: >lua
    -- Vorher:
    local ft = vim.api.nvim_buf_get_option(bufnr, "filetype")
    local ft = api.nvim_buf_get_option(0, "filetype")

    -- Nachher:
    local ft = vim.api.nvim_get_option_value("filetype", { buf = bufnr })
    local ft = api.nvim_get_option_value("filetype", { buf = 0 })
<

Set: >lua
    -- Vorher:
    vim.api.nvim_buf_set_option(bufnr, "filetype", "lua")
    api.nvim_buf_set_option(0, "modifiable", false)

    -- Nachher:
    vim.api.nvim_set_option_value("filetype", "lua", { buf = bufnr })
    api.nvim_set_option_value("modifiable", false, { buf = 0 })
<

WINDOW OPTIONS~

Get: >lua
    -- Vorher:
    local wrap = vim.api.nvim_win_get_option(winid, "wrap")
    local wrap = api.nvim_win_get_option(0, "wrap")

    -- Nachher:
    local wrap = vim.api.nvim_get_option_value("wrap", { win = winid })
    local wrap = api.nvim_get_option_value("wrap", { win = 0 })
<

Set: >lua
    -- Vorher:
    vim.api.nvim_win_set_option(winid, "number", true)
    api.nvim_win_set_option(0, "relativenumber", false)

    -- Nachher:
    vim.api.nvim_set_option_value("number", true, { win = winid })
    api.nvim_set_option_value("relativenumber", false, { win = 0 })
<

KOMPLEXE EXPRESSIONS~

Das Modul erhält alle Expressions: >lua
    -- Vorher:
    vim.api.nvim_buf_set_option(
      vim.fn.bufnr("%"),
      "expandtab",
      vim.bo.expandtab
    )

    -- Nachher:
    vim.api.nvim_set_option_value(
      "expandtab",
      vim.bo.expandtab,
      { buf = vim.fn.bufnr("%") }
    )
<

PREFIX-VARIATIONEN~

Das Modul erkennt verschiedene Prefix-Stile: >lua
    vim.api.nvim_buf_get_option(...)     → vim.api.nvim_get_option_value(...)
    api.nvim_buf_get_option(...)         → api.nvim_get_option_value(...)
    nvim_buf_get_option(...)             → nvim_get_option_value(...)
<

6. API REFERENZ                                              *migrate-opt-api*

MIGRATION MAPPING:

Buffer Get~
    nvim_buf_get_option(bufnr, "opt")
    → nvim_get_option_value("opt", { buf = bufnr })

Buffer Set~
    nvim_buf_set_option(bufnr, "opt", value)
    → nvim_set_option_value("opt", value, { buf = bufnr })

Window Get~
    nvim_win_get_option(winid, "opt")
    → nvim_get_option_value("opt", { win = winid })

Window Set~
    nvim_win_set_option(winid, "opt", value)
    → nvim_set_option_value("opt", value, { win = winid })

PATTERN DETAILS:

Das Modul verwendet Lua-Patterns für Detection: >lua

    -- Pattern für nvim_buf_set_option:
    'nvim_buf_set_option%(%s*([expr])%s*,%s*(["\'])(.-)%2%s*,%s*([expr])%s*%)'

    -- Captured groups:
    -- 1: bufnr expression
    -- 2: quote type (' oder ")
    -- 3: option name
    -- 4: value expression
<

EXPRESSION PRESERVATION:

Alle Expressions bleiben intakt: >lua
    -- Input:
    api.nvim_buf_set_option(
      state.bufnr or 0,
      "modifiable",
      config.allow_edit
    )

    -- Output (alles erhalten):
    api.nvim_set_option_value(
      "modifiable",
      config.allow_edit,
      { buf = state.bufnr or 0 }
    )
<

7. TROUBLESHOOTING                              *migrate-opt-troubleshooting*

PROBLEM: "ripgrep (rg) not found"~

  URSACHE:
    CWD-Mode benötigt ripgrep für schnelles File-Scanning

  LÖSUNG:
    Installiere ripgrep: >bash
    # Ubuntu/Debian
    apt install ripgrep

    # macOS
    brew install ripgrep

    # Windows (scoop)
    scoop install ripgrep
<

PROBLEM: "No matches found"~

  URSACHEN:
    • File ist nicht vom Typ 'lua'
    • Bereits migriert zur neuen API
    • Ungewöhnliche Formatierung

  LÖSUNG:
    Prüfe manuell ob deprecated API-Aufrufe existieren

PROBLEM: Pattern in Strings wird migriert~

  BEISPIEL: >lua
    local example = 'api.nvim_buf_get_option(0, "ft")'
<

  LÖSUNG:
    Bekannte Limitation - Patterns in Strings werden erkannt.
    Manuell rückgängig machen nach Migration.

PROBLEM: Komplexe nested Expressions werden nicht erkannt~

  BEISPIEL: >lua
    api.nvim_buf_set_option(
      get_buffer(opts.target or vim.fn.bufnr()),
      "ft",
      compute_type(opts)
    )
<

  LÖSUNG:
    Das Regex-Pattern hat Grenzen bei stark nested Expressions.
    In solchen Fällen: Manuell migrieren.

PROBLEM: Multiline-Aufrufe werden nicht erkannt~

  URSACHE:
    Das opt-Modul arbeitet Line-by-Line (im Gegensatz zu notify)

  LÖSUNG:
    Formatiere auf Single-Line, dann migriere:
    >lua
    -- Vorher (multiline):
    api.nvim_buf_set_option(
      bufnr,
      "filetype",
      "lua"
    )

    -- Format auf single line:
    api.nvim_buf_set_option(bufnr, "filetype", "lua")

    -- Dann migriere
<

NEOVIM VERSIONS-KOMPATIBILITÄT~

  Die neue API existiert seit:
    • nvim_get_option_value: Neovim 0.9+
    • nvim_set_option_value: Neovim 0.9+

  Die alten APIs sind deprecated seit:
    • Neovim 0.10+

  Wenn du Neovim < 0.9 unterstützen musst, migriere NICHT.
