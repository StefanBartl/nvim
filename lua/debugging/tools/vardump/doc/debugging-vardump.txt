1. INTRODUCTION                                *debugging-vardump-introduction*

Vardump is a universal debugging tool for inspecting Lua variables and
complex data structures. It provides recursive traversal of nested tables,
metatables, and handles all Lua data types with proper formatting.

Similar to PHP's var_dump(), vardump makes it easy to understand program
state by displaying variable contents in a human-readable format.

==============================================================================
2. USAGE                                              *debugging-vardump-usage*

Basic usage:~
>lua
    local Vardump = require("debugging.vardump")

    local myvar = { foo = "bar", nested = { a = 1, b = 2 } }
    Vardump(myvar)
<

Output:~
    (table)
    [foo] = (string) bar
    [nested] = (table)
      [a] = (number) 1
      [b] = (number) 2

3. EXAMPLES                                        *debugging-vardump-examples*

Simple value:~
>lua
    local Vardump = require("debugging.vardump")

    Vardump("Hello World")
    -- Output: (string) Hello World

    Vardump(42)
    -- Output: (number) 42

    Vardump(true)
    -- Output: (boolean) true
<

Nested tables:~
>lua
    local data = {
        name = "Alice",
        age = 30,
        skills = { "lua", "vim", "neovim" },
        config = {
            theme = "dark",
            font = { size = 14, family = "monospace" }
        }
    }

    Vardump(data)
<

Output:~
    (table)
    [name] = (string) Alice
    [age] = (number) 30
    [skills] = (table)
      [1] = (string) lua
      [2] = (string) vim
      [3] = (string) neovim
    [config] = (table)
      [theme] = (string) dark
      [font] = (table)
        [size] = (number) 14
        [family] = (string) monospace

Mixed types:~
>lua
    local mixed = {
        1, 2, 3,
        {
            1,
            { 1, 2, 3, 4, { 1, 2, { 1, "cool", 2 }, 4 }, 6 },
            3,
            Vardump,
            5,
            6
        },
        5,
        { Mary = 10, Paul = "10" },
        "last value"
    }

    Vardump(mixed)
<

Output:~
    (table)
    [1] = (number) 1
    [2] = (number) 2
    [3] = (number) 3
    [4] = (table)
      [1] = (number) 1
      [2] = (table)
        [1] = (number) 1
        [2] = (number) 2
        [3] = (number) 3
        [4] = (number) 4
        [5] = (table)
          [1] = (number) 1
          [2] = (number) 2
          [3] = (table)
            [1] = (number) 1
            [2] = (string) cool
            [3] = (number) 2
          [4] = (number) 4
        [6] = (number) 6
      [3] = (number) 3
      function: 0x304650
      [5] = (number) 5
      [6] = (number) 6
    [5] = (number) 5
    [6] = (table)
      [Mary] = (number) 10
      [Paul] = (string) 10
    [7] = (string) last value

Metatables:~
>lua
    local tbl = { value = 42 }
    setmetatable(tbl, { __index = function() return "default" end })

    Vardump(tbl)
<

Output:~
    (table)
    [value] = (number) 42
    (metatable)
    [__index] = function: 0x123456

4. FEATURES                                        *debugging-vardump-features*

Type detection~
    • string, number, boolean, nil
    • table (with recursive traversal)
    • function (with memory address)
    • thread, userdata

Formatting~
    • Indentation based on depth (2 spaces per level)
    • Type annotation: (type) value
    • Table keys in square brackets: [key] = value

Metatable support~
    • Detects and displays metatables
    • Shows metatable contents recursively

Recursion handling~
    • Unlimited depth (no artificial limits)
    • Each nesting level indented by 2 spaces

Mixed key types~
    • Numeric indices: [1], [2], [3]
    • String keys: [name], [config]
    • Mixed tables handled correctly

5. API                                                  *debugging-vardump-api*

Vardump({value}, {depth}, {key})                              *Vardump()*
    Recursively print variable contents.

    Parameters:~
        {value}  (any) Variable to inspect
        {depth}  (number|nil) Current recursion depth (internal use)
        {key}    (any|nil) Table key for current value (internal use)

    Returns:~
        nil (output printed to stdout)

    Notes:~
        • depth and key are for internal recursion
        • Users typically only pass value
        • No return value - prints directly

    Example: >lua
        local Vardump = require("debugging.vardump")
        Vardump({ foo = "bar", baz = { 1, 2, 3 } })
<

6. LIMITATIONS                                  *debugging-vardump-limitations*

Circular references~
    Vardump does not detect circular references. If a table references
    itself, vardump will recurse infinitely until stack overflow.

    Example of problematic code: >lua
        local tbl = {}
        tbl.self = tbl  -- Circular reference
        Vardump(tbl)    -- Will cause stack overflow
<

    Workaround: Break circular references before dumping or implement
    cycle detection.

No depth limit~
    Vardump has no built-in depth limit. Very deep nested structures
    may cause performance issues or stack overflow.

    Workaround: Manually limit nesting or implement max_depth parameter.

Large tables~
    Dumping very large tables (1000+ keys) may produce overwhelming output.

    Workaround: Consider sampling or filtering before dump.

Function details~
    Functions show only memory address, not source code or parameters.

    Example: >lua
        Vardump(function() return 42 end)
        -- Output: function: 0x123456
<

Userdata~
    Userdata objects show only type, no internal structure.

    Example: >lua
        Vardump(vim.loop)
        -- Output: userdata: 0x789abc
<

Performance~
    Vardump uses print() for each line, which is not optimized for
    very large outputs. For production use or large dumps, consider
    buffering output.
